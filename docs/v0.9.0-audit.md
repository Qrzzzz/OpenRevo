# OpenRevo 0.9.0 验收记录

日期：2026-10-22。

## 范围与实现

冻结监控与四模式功能，集中处理界面消息压力、连接状态和原生交互。核心控制代码、协议命令、机型／能力／配置门槛与诊断 schemaVersion 4 不变。

监控核心继续逐条处理所有消息，界面改为每个主题仅保留最新样本，按原有一秒定时器和用户操作刷新。缓冲最多包含七个主题，接收计数不合并；源时间戳、RETAIN 标记和 JSON 原值保留。每次连接拥有独立缓冲，结束和诊断保存前排空最后的界面样本。此改动不影响核心的两次回读判据。

连接活动状态不再从尚未返回的 Task 推断。断开请求立即禁用刷新和模式动作，显示正在断开；完成时显示历史数据，晚到的旧连接通知不会重新标为已连接。异常日志的目录创建也纳入已有的写入失败处理。

系统对比度主题采用窗口级 ThemeSettings 接口，标题栏前景使用系统对比度颜色，退出时移除监听。参考 [Microsoft 对比度主题指南](https://learn.microsoft.com/en-us/windows/apps/design/accessibility/high-contrast-themes)与 [ThemeSettings](https://learn.microsoft.com/en-us/windows/windows-app-sdk/api/winrt/microsoft.ui.system.themesettings)。

## 首轮失败与修复

首轮原生候选因误用 UWP AccessibilitySettings.HighContrastChanged 事件而在启动阶段退出；本机 Windows 事件与 crash.log 留有记录，未计入成功运行。已改为 Microsoft.UI.System.ThemeSettings.CreateForWindowId，在窗口加载后注册 Changed，重新启动并连接成功。初次失败日志留在本机 `.local/evidence/v090-initial-startup-failure.log`。

## 资源观察

首轮进程实际采集 25 个独立样本，间隔约 30 秒，覆盖约 12 分钟。工作集范围 231.3–338.7 MiB；私有内存首末为 129.4／213.6 MiB，句柄首末为 1,016／1,131。该时段包含页面首次显示、系统对比度主题切换、导出选择器与重复实例交互，不能直接解释为内存泄漏，也不能据此写成没有持续增长。

继续采集已预热进程及 System.Runtime 计数器，以分开判断托管堆、分配与进程内存；使用 dotnet-counters 10.0.750501（官方 NuGet 工具），仅保存在本机 `.local/tools`，不进入发行包。没有采集包含对象内容的内存转储。

预热进程额外采集 13 个样本，覆盖约六分钟，其中后半段附加诊断计数器；私有内存首末为 231.48／276.75 MiB，末五个样本在 273.54–276.75 MiB 波动，句柄首末为 1,139／1,111。主题切换、首次绘制、重连和诊断附加的影响没有被排除，不能与冷启动作无开销对照。

System.Runtime 连续采集约三分钟，36 组完整的堆代际样本；最后一次 GC 的堆大小合计从 12.07 MiB 回落到 3.28 MiB，包含 LOH 的明显回收。当前窗口没有发现托管存活堆持续增长的证据，末段进程内存没有持续单向增加；这不证明长期不存在泄漏。原始 CSV SHA256：`eb5286124dc683772c6fe1b74f85e9e165d80163bc1f40e0efe7adec49e0c0b4`。汇总见本机 `.local/validation/v090-resource-summary.json`。
