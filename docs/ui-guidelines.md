# 0.7.0 界面与文案审查

按 Apple HIG 的信息层级、清晰表达、操作一致性和渐进展示原则优化，使用 Windows 原生 WinUI／Fluent 控件实现。

参考：[Layout](https://developer.apple.com/design/human-interface-guidelines/layout)、[Writing](https://developer.apple.com/design/human-interface-guidelines/writing)、[Buttons](https://developer.apple.com/design/human-interface-guidelines/buttons)、[Windows 应用设计](https://learn.microsoft.com/en-us/windows/apps/design/)。这是一轮针对当前应用的问题修正，不宣称完成全部平台可访问性认证。

| 原问题 | 0.7.0 调整 | 判断依据 |
| --- | --- | --- |
| 刷新、断开、导出只在概览页 | 移到全局连接栏；窄窗口分为两行 | 常用操作位置稳定，状态在不同页面可见 |
| 模式按钮先于当前模式，恢复用语不明确 | 先显示当前模式／供电，再显示可用状态和等宽选择；改为“撤销上次切换”“保留此模式” | 用动作表达操作，关联的选项保持一致 |
| 切换记录和长说明挤占主界面 | 关键结果用信息栏，配置、记录、操作说明放入可展开详情 | 关键内容优先，研究信息按需查看 |
| 未开放功能与已开放功能等量展示 | 先显示监测和模式，其他功能归组折叠 | 减少无效选择，避免“能力位”被误解为可操作 |
| matched、会话枚举、协议主题直接显示 | 主流程采用中文状态；设备指纹和字段保留在详情及原始数据中 | 面向日常用户写作，保留排查入口 |
| 设置页混合说明、底层策略和诊断 | 分为外观、设备连接、问题排查及适用范围 | 按用户任务组织信息 |
| 旧数据靠降低数值透明度显示 | 数值保持可读，用文字注明缓存、未更新、历史状态 | 不依赖颜色／透明度区分状态 |
| 原始 JSON 主题不易辨认 | 数据来源使用中文名称，元数据仍显示协议主题；解释暂停只冻结画面 | 标签明确，不改变监测行为 |
| 暂停后冻结的“0 秒前”容易被理解为实时状态 | 改为“画面已暂停”和绝对快照时间 | 状态反馈与画面实际行为一致 |
| 紧凑导航按钮与标题重叠、浅色全局栏对比不足 | 显示模式改变时调整顶部留白；根背景跟随主题资源 | 布局适应窗口，文字在主题切换后保持可读 |
| 导出完成没有反馈 | 显示可关闭的成功信息与保存位置；取消不报错 | 操作反馈与实际结果对应 |

## 一致用语

- 性能模式：用户切换入口；配置详情保留原字段名，诊断 JSON 不改字段。
- 撤销上次切换：恢复最近一次切换前的模式和配置，不表示恢复出厂设置。
- 保留此模式：结束本次恢复记录，不发送新的模式命令。
- 保存诊断报告：保存本地 `audit-review.json`，供排查与重新验证；不自动上传或批准版本。
- 原始数据：用于排查的状态 JSON，暂停画面更新不会停止后台监测。

保留 Ctrl+R、Ctrl+S 和标准 Tab／Shift+Tab、Enter／空格操作。按钮是否可用仍由既有控制层决定，不在界面层放宽机型、能力、供电或恢复条件。模式控制异常的底层详情不隐藏于导出材料之外，仍可展开查看。
