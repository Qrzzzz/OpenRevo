# OpenRevo 0.4.0 稳定性验收

本版聚焦会话稳定性、传感器缺失诊断、供电与睡眠场景，不扩展可写硬件参数或机型范围。制定和实机验证日期：2026-10-21。本机验收与 GitHub 构建、发布分别记录；云端构建不代表硬件验收。

## 实现

- 单个传感器缺失或长时间未推送只作提示，其他状态继续使用，不因此断开连接或撤销模式能力。刷新沿用既有 GETSUPPORT、GETSTATUS、System_ON，不自动循环恢复采样。
- 会话统计记录七个固定主题的实时／缓存收包数、最后接收与内容变化时间、相邻实时响应最大间隔、请求计数和结束原因。事件最多 64 条，界面保留最近八个已结束会话摘要。
- 使用已有 Windows App SDK 电源通知。电池供电通知及时更新模式条件，无需等待下一次厂商状态；监测继续运行，不接管硬件策略。
- 收到传统睡眠通知时结束连接，唤醒后可手动重连，不重放模式命令。本机实际为联网 S0 现代待机：连接正常时继续监测，不因待机或屏幕状态额外强制断开。真正断线后仍按现有诊断提示手动重连。
- 诊断升级为 schemaVersion=3，包含 sessionHealth、previousSessions 和电源通知可用性；连接结束时自动保存本地诊断。探针队列裁剪标为 trimmedMessages，不将本机保留上限误称网络丢包。

## 验证结果

| 项目 | 结果与范围 |
| --- | --- |
| 自动化 | 69/69 通过，包含传感器完全静默、供电在写前／回读中改变、传统睡眠中断，以及模拟服务重启后的新握手与不重放 |
| 持续实机观察 | CLI 观测候选约 30 分钟，2,141 条消息，239 次查询／采样请求，System_ON 仅一次，零错误、零队列裁剪、零模式命令；七个主题均有实时回报 |
| 主题间隔 | CPU 最大约 2.03 秒，风扇约 2.15 秒，GPU 约 176.45 秒，电池约 61.39 秒；单传感器静默未导致断连 |
| 进程采样 | 53 次采样，工作集 50.55–56.68 MB；此项是观察范围，不能据此证明不存在长期内存泄漏 |
| 重复实例 | 实际第二探针零请求退出，原生窗口正确显示 SlotOccupied，原观察继续运行 |
| AC/DC | Windows 与厂商状态均记录交流电→电池→交流电；用户明确确认电池供电时模式按钮禁用，交流电恢复后按钮可用，监测未中断 |
| S0 现代待机 | powercfg 与 Kernel-Power 506/507 证实本机为联网 S0，11:19:47–11:19:56 往返约 8.84 秒；同一应用会话继续接收实时状态，没有额外握手或模式命令 |
| 手动断开／重连 | 实际界面操作通过；断开保留历史值，新会话取得实时能力、配置、CPU 与风扇数据；没有模式重放 |
| 传统睡眠 | 仅模拟验证 SystemSuspended；本机不支持 S3，未宣称完成 S3 实机验收 |
| 服务重启 | 按用户选择仅模拟：应用模式已生效后断开服务连接，旧状态变为 Interrupted；重连先等待实时能力，缓存不能授权，不重放旧控制。未重启真实 GCUBridge 或 GCUService |

最终便携版 WinUI 完成供电、S0 与手动重连交互；持续观察由 CLI 候选执行。原始诊断留在 .local/evidence，公开摘要、来源 SHA256 和真实／模拟范围见 protocol/stability-evidence.json。可在保留本机原始输入时运行 scripts/summarize-stability-evidence.py 复核；CI 不需要这些私有原始记录。

观察过程中厂商状态后来报告狂暴模式；OpenRevo 所有实机观察与重连记录均无 OPERATING_* 命令，本轮没有回写或恢复模式。

## 构建与边界

沿用 0.3.0 的四种固定模式命令、交流电和精确机型／后台／配置条件。既有四模式证据仍在 protocol/mode-evidence.json。没有增加任意主题发布、驱动访问或额外传感器拦截。

本机 WinUI Release 构建及便携包依赖、源文件与 SHA256 校验通过。公开构建与发布资产以对应 GitHub Actions 运行与 Release 为准。无风扇曲线、色彩、电池阈值和自定义功耗参数编辑。原厂服务没有控制事务或 CAS。30 分钟观察不代替全天／多日运行；固件故障、断电、过温和真实服务重启不在本次实机结论内。
