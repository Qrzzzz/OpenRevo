# OpenRevo 1.1.0 验收记录

日期：2026-10-23。沿用 1.0 的已验证主板、BIOS 和 GCUBridge／GCUService 指纹，本版新增一键强冷开关及手动 GitHub 更新检查。

## 原厂协议与本机观察

本轮重新检测本机设备与两项后台文件，身份均匹配。原厂 ControlCenter3 5.56.51.49 的入口为自定义模式 → SPC 设置 → 页面下方“风扇控制”→“一键强冷”。仅进入该自定义模式并观察强冷按钮，不修改曲线、灵敏度、CPU／GPU 参数。原厂发送 `Fan/Control` 的 `FAN_BOOST_ON`／`FAN_BOOST_OFF`，没有附带调速参数，状态为 `FanBoostEnable` 的字符串 `1`／`0`。

原厂开启／关闭记录 `.local/evidence/v110-vendor-fan-roundtrip.json`：状态 0 → 1 → 0，完整配置起止无差异；两路风扇达到 100% 占空比，最高约 5133／5205 RPM，随后回落。原始记录只保存在本地；可发布摘要及 SHA256 在 `protocol/fan-boost.json`。公共 EC 地址仍有分支歧义，本版不访问驱动或直接 EC。

## 独立控制与恢复

原厂前端关闭后，通过现有 GCUBridge 连接独立发送两条已观察动作。`.local/evidence/v110-fan-independent.json` 中狂暴模式开启和关闭各一次，每次均有两次新鲜回读确认，除强冷字段外其他配置不变。CPU／GPU 风扇达到 100%，约 5133／5295 RPM；恢复后降至约 2655／2735 RPM。转速是本次条件下的观察值，不是固定转速承诺。

`.local/evidence/v110-fan-other-modes.json` 进一步完成办公、均衡、自定义模式的开启／关闭与完整配置恢复，再切回初始狂暴模式；原始配置最终完全恢复。自定义始终使用已有 Profile1，不编辑用户配置。

写入前重新查询能力与完整配置，在共享发送锁内再次确认；模式操作和风扇操作共用忙碌状态。风扇写入保存本地基线，命令只发送一次，等待两次至少间隔 500 ms 的新鲜 `Fan/Status`，要求模式与其他配置不变。保留消息不作确认，超时、断线、供电变化或失败后不自动重发或恢复。强冷字段只有已验证的 0／1 可以作为独立可变状态，未知值及其他配置差异仍需检查。配置基线比较仍保持严格。

强冷开启时先恢复自动调速，再切换性能模式；风扇操作结束此前的模式撤销记录。关闭、断线、唤醒和重新打开不自动写风扇设置，原厂后台继续负责温控。后台程序没有新增轮询或硬件连接。

## GitHub 更新检查

仅用户点击时向固定公共 `api.github.com/repos/Qrzzzz/OpenRevo/releases/latest` 发起无令牌 GET，读取正式版版本号、说明及本仓库对应资产地址。按数字比较三段版本，区分有更新、已是当前版本及本地版本较新；网络故障、12 秒超时、403／429 限流、404 无正式版和异常响应分别结束检查，并允许手动重试。关窗取消请求。下载由浏览器完成，不在后台联网或执行更新程序。

真实网络检查 `.local/evidence/v110-github-check.json` 成功查询 v1.0.0；本地候选 1.1.0 正确识别为高于已发布版本。原生界面另一次检查遇到 GitHub 未登录 API 限流，因此补充 403／429 降级：仅请求一次 GitHub 官方 `releases/latest`，从本仓库对应正式版本跳转地址确认版本，不读取整个网页；此路径只提供发布页入口，不猜测下载资产存在。`.local/evidence/v110-github-fallback.json` 已真实验证限流时仍可识别最新版本。响应契约参见 [GitHub 官方 Releases API](https://docs.github.com/en/rest/releases/releases#get-the-latest-release) 和[官方最新发行链接](https://docs.github.com/en/repositories/releasing-projects-on-github/linking-to-releases)。本功能提供检查及下载入口，不是自动安装器。
