# 身份、配置差异与重新审计

0.6.0 将识别拆为三个独立层次。

| 层次 | 核对内容 | 不匹配时 |
| --- | --- | --- |
| 安装身份 | 制造商、型号、主板、BIOS、桥接和核心服务的大小／SHA256 | 停止连接，列出实际值及审计值 |
| 实时能力 | 五项项目／平台身份与两项监控就绪条件；模式及狂暴分别检查各自能力位 | 身份或监控就绪不符时停止会话；单项功能能力不足只限制相应控制 |
| 模式配置 | 平台身份、85 项控制配置、独立的模式和供电状态 | 关键配置变化时停止性能模式；通知和时间戳不影响配置指纹 |

字段分类见 `protocol/configuration-policy.json`。91 个已知 Fan/Status 字段中，两项平台身份、两项实时状态、两项通知／历史字段、85 项控制配置全部明确归类；新增未知字段需审计。`BSOD_DefaultNotify` 和 `BSOD_TimestampRestored` 的排除依据为字段用途和仅出现在状态模型中的本地静态线索，不代表已恢复受保护处理方法或验证蓝屏行为。`FAN_SafetyProtect`、保护通知、温度边界等未因名称相似而排除。

`OperatingMode` 允许厂商已观察到的 null 表示，但必须由唯一的关键配置指纹识别；原始 null 保留。`IsAC` 不作为机型或配置指纹，仍由厂商实时供电与 Windows 通知约束控制。交流电和电池切换不能借此绕过门槛。通知字段不再参与两次回读和恢复配置比较；其他字段依旧比较。

## 操作流程

1. 连接失败时，在“设置与诊断”核对差异：主板／BIOS、服务哈希和文件大小分别显示。模式按钮不可用时，在“性能模式”查看原因和关键字段差异。
2. 点击“保存诊断报告”，生成 `%LOCALAPPDATA%\OpenRevo\audit-review.json`。schemaVersion 4 包含安装期望／实际差异、能力差异、当前配置差异、字段策略和原始回报；不含认证口令。材料只保存本机，不自动上传。
3. 如果是原厂配置被修改，先在原厂界面核对并恢复受支持的已保存配置。若是 BIOS、后台或新机型发生变化，需独立分析、补充配置和回读／恢复证据，然后由受审查的版本更新支持。
4. 恢复到支持范围后，断开并点击“重新检测并连接”。每次都重新读取注册表和服务指纹；连接中不可点击，以免打断正在进行的操作。

保存材料与重新检测均不会加载 JSON 来批准新版本，不提供跳过校验或自动更新可信哈希的入口。也无需因普通传感器变化、其他功能能力位变化、蓝屏通知偏好或历史时间戳变化重新审计。
