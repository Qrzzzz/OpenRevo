# OpenRevo 0.3.0 审计与验收

本版支持原厂办公、均衡、狂暴和已保存自定义配置的模式切换。自定义只激活当前已保存配置，不编辑功耗参数、配置索引或风扇曲线。均衡模式的协议动作保留厂商名称 `OPERATING_GAMING_MODE`；办公为 `OPERATING_OFFICE_MODE`，均发送到 Fan/Control，QoS 0、retain=false。

## 控制与恢复条件

严格匹配嵌入的主板、BIOS、服务文件及实时能力；要求交流电、新鲜非 retained 状态与已审计的完整配置组合。保存本地基线和操作日志后才发送，重复点击不排队。每次一条命令，等待至少间隔 500ms 的两次一致配置回读。恢复需用户单独点击、同一连接且当前配置仍与已确认目标一致，随后核对所有回报字段和字段集合。界面展示的 PL/TGP 是配置值，不是实时功耗。

转换期间原始 OperatingMode 可能为 null；保留原始值，通过精确审计配置指纹识别。实验采集额外使用实时 Tray 状态交叉核对。无法确认、断线、能力降级或检测到外部修改后停止，不自动重试、回滚或跨会话重放。日志写入失败时拒绝发送。未恢复日志只供提示与诊断。

## 实机证据

2026-10-19 本机交流电验证：首轮发送一条均衡命令后，因 Fan/Status 的模式暂时为空而停止，未发送恢复；用户已用原厂界面恢复办公。随后修复回读判定，并增加对应测试。

第二轮完成办公 → 均衡 → 办公：仅两条模式命令，切换与恢复均经两次一致回读确认，恢复后 **91 个回报字段及字段集合全部与基线相同**。最终模式为办公，状态为 Restored。脱敏配置证据与原始记录 SHA256 见 `protocol/mode-evidence.json`，门控策略见 `protocol/mode-pilot.json`；原始记录保留在被忽略的 `.local/evidence/`。

新增两轮实际验证：办公 → 狂暴 → 办公，办公 → 原厂已保存自定义配置 → 办公。目标模式分别回读为 2 和 3，配置为 Mode3_Profile1/M3T1、Mode4_Profile1/M4T1。每轮仅两条模式命令，回读与恢复成功，91 个字段全部恢复一致。所有三轮都由实时 Tray 状态交叉核对；新增原始记录 SHA256 与命令序列列在 mode-evidence.json 的 additionalTrials 中。当前精确配置索引均为 0，不泛化到其他用户配置。

所有四个模式作为目标和基线均须匹配审计配置；狂暴另要求实时 TurboModeSupport=1。自动化也覆盖狂暴、自定义作为原模式的恢复，以及原厂自定义配置索引改变时拒绝发送。

## 验证范围

自动化覆盖协议编码、受限模式域、交流电前置条件、日志失败、缺失响应、重复点击、无变化请求、超时无重试、外部修改拒绝恢复、断线不重放、模式暂时为空及精确配置指纹。构建与便携包身份另行核验；云端测试不操作硬件。

尚无断电、睡眠或固件故障的实机注入验证；所有回报字段恢复不证明未回报的固件寄存器恢复。原厂服务无事务或 CAS，仍存在校验与发送间的并发窗口；请勿同时用其他控制器修改模式。受保护的核心服务方法体仍未完整恢复。无直接驱动／EC 写入，无任意参数控制，无风扇曲线、色彩、电池阈值或自定义参数编辑。本地候选构建与 GitHub 发布分别记录。


## 四模式候选验收

60 项自动化检查通过，WinUI 构建无警告、无错误。实际便携版界面已分别执行办公 → 狂暴 → 恢复办公、办公 → 原厂已保存自定义配置 → 恢复办公。每次目标经两次一致回读确认，界面显示“已恢复”，本地日志记录 Restored、ConfirmedMode=0；两轮 91 个字段回到各自基线。最终机器保持办公模式。便携 ZIP、源文件身份与应用程序哈希校验通过。以上为本地候选验收，未推送或发布 0.3.0。
