# OpenRevo 1.0 验收范围

1.0 定位为已审计机型上的本机监控与四模式日常控制工具，继续依赖原厂 GCUBridge／GCUService。主板、BIOS、后台文件与已保存自定义配置的支持范围沿用当前证据；其他机型不能据此视为兼容。

## 功能冻结

包括硬件监控、四模式切换／回读／保留／撤销最近基线、原始数据、诊断导出、主题与窗口状态保存，以及用户追加的可选开机自启动与轻量托盘。托盘只负责唤起界面，不独立接管硬件或持续采样。不新增风扇曲线、充电阈值、色彩、功耗编辑、跨连接恢复或替代原厂服务的独立控制后台。其他新功能不作为 1.0 发布前提。

## 收尾条件

| 项目 | 判断条件 | 证据位置 |
| --- | --- | --- |
| 控制与恢复 | 原有四模式回读／恢复检查通过；客户端维护不改变硬件策略 | 0.3–0.6 审计、mode-evidence.json、当前自动检查 |
| 日常运行 | 至少两个独立原生会话，覆盖切页、暂停画面、导出、断开／重连、退出与重开；记录资源变化并解决可复现的严重问题 | 0.9.0 审计与本机原始记录 |
| 用户操作 | 关键操作可用键盘完成，成功／取消／失败可区分，断线后的值有历史标记；主题与对比度问题分别记录 | 0.7–0.9 原生验收 |
| 启动与后台 | 自启动默认关闭且可撤销；关窗释放界面，托盘能重开／退出；记录独立托盘的实际资源占用 | 0.10.0 审计 |
| 发行 | 支持范围与限制明确；最终候选构建、包身份、CI、发布资产下载校验通过 | README、版本审计、工作流与 Release |

会话观察只代表记录的时段，不宣称已经证明多日无故障。1.0 前继续正常使用；发现影响监控、切换、恢复或退出的问题就修复，不用重复硬件写入或堆叠无关测试代替处理问题。

## 已接受的边界

服务重启按用户要求只做模拟；本机 S0 待机与拔插供电沿用 0.4 的实测，未提供的传统 S3 不构成阻塞。不同显示器、屏幕阅读器实际播报及系统对比度主题，按本机实际执行情况说明，不以 UI Automation 树代替听取播报。

便携 ZIP、自包含运行、未签名和无自动更新属于当前发行方式。明确更新与回退说明即可；安装器、签名、多机型和自动更新可以后续安排。所有未执行项及已知问题在发布说明中如实列出。
