# MVP 审计与验收记录

日期：2026-10-18。本轮目标是补齐本机能力与状态读取证据，按审计结果交付 Windows 11 原生 MVP。

## 本机与适用范围

实际读取的主板为 `YAOSHI Series-X6AR55xY`，BIOS 为 `N.1.18MRO24`，厂商为 MECHREVO。服务实时能力响应同时给出 `ProjectID=26`、`BIOS_PROJECT_ID=IDY`、`CustomizeTarget=56`；这些关联来自本机响应，未外推到其他机型。

MVP 校验这组主板 / BIOS，以及 GCUBridge、GCUService 的已审计 SHA256。未知机型、BIOS 或服务版本停止连接，提示重新审计。认证格式在本地从已核对的安装文件读取，不进入日志、诊断导出或源码。

这个版本复用已安装的厂商后台，尚未替代 GCUService 或驱动。没有卸载或修改原厂服务、驱动、注册表配置、BIOS / EC 或硬件控制参数。

## 实际协议证据

机器可读记录：[live-evidence.json](../protocol/live-evidence.json)。文件包含原始观察文件的 SHA256、各主题数量和字段类型；完整原始记录留在本机 `.local/evidence/`。

| 观察 | 实际结果 |
| --- | --- |
| 仅订阅，20 秒 | 1 条 retained 能力声明；没有传感器推送 |
| 原托盘查询，15 秒 | 能力实时响应、Fan/Status 实时响应；发送 GETSUPPORT、GETSTATUS |
| 观察原厂监控页，55 秒 | 捕获 System_ON / System_OFF 和实际传感器消息；观察器自身未发布业务消息 |
| 关闭原厂前端后独立读取，15 秒 | 发送两条查询与 System_ON；收到 CPU、GPU、两路风扇、电量等实时消息 |
| C# 读取后端，18 秒 | 24 条消息、5 次查询、无错误；包括周期配置刷新。该轮未收到 GPU 更新，未使用其他轮次值冒充实时数据 |

五次成功观察共 85 条消息。另一次早期 55 秒观察因未发送保活而被服务断开，已补上 PINGREQ；该失败不计入成功观察，未拿它证明持续连接成功。

本机端口为 `127.0.0.1:13688`，已实测 MQTT 3.1.1 握手。独立读取使用 PluginClient 的 19 号槽位，与原托盘固定的 UWPClient_10 分开。文件占用锁避免 OpenRevo / 本项目观察器相互抢占同一槽位；没有证明其他未知第三方客户端永不使用该厂商槽位，因此不做自动槽位扫描或重连抢占。

## MVP 开放与保留的功能

| 功能 | MVP 行为 | 证据或限制 |
| --- | --- | --- |
| 本机识别 | 展示型号、主板、BIOS、服务指纹 | Windows 注册表只读信息 + 安装文件哈希 |
| 能力识别 | 展示原始能力位及审计状态 | 实时 Customize/SupportInfo；非零编码不等于控制已验证 |
| CPU / GPU | 温度、占用；未知时显示破折号 | 实际监控响应；单位与原厂监控页面核对 |
| 风扇 | CPU/GPU 转速与占空比 | 实际 System/FanInfo，保留 JSON 数值类型 |
| 电池 | 电量、供电状态 | 实际 BatteryLifePercent 与 IsAC；不把容量 0、剩余时间 -1 当作有效健康结论 |
| 模式与功耗配置 | 展示模式及厂商配置原值 | Fan/Status；配置不是实时功耗，不添加未经确认的物理单位 |
| 原始数据 | 主题选择、只读 JSON、暂停显示更新 | 未知字段保留；不提供通用发布入口 |
| 诊断 | 保存本地 JSON，含接收时间、RETAIN、查询记录 | 不含认证信息；不发送网络报告 |
| 色彩、曲线、电池阈值、功耗 / 超频、独显切换 | 不开放写入 | 参数、联动、恢复或本机语义的证据不完整 |

风扇状态实时返回 `GPU_ConfigurableTGPTarget=140`，同一响应的 Maximum 却为 `115`。MVP 明确显示矛盾并保留原值，不钳制后写回，不把厂商配置转换为可写滑块。

## 查询边界与新鲜度

运行时代码只允许三种固定请求：

| 主题 | Action | 用途 |
| --- | --- | --- |
| Customize/SupportControl | GETSUPPORT | 查询能力 |
| Fan/Control | GETSTATUS | 查询配置状态 |
| System/Control | System_ON | 启用厂商监控采样计时器 |

没有通用 Publish API；所有业务发送均 QoS 0、retain=false。订阅仅七个明确状态主题，QoS 0，clean session，无 will。连接仅限 IPv4 loopback。不会调用厂商 DLL 或驱动。

System_ON 会改变厂商后台的采样计时器状态；它不是硬件参数写入，但也不是完全没有后台副作用。厂商计时器是共享的，没有按客户端所有权契约，因此本应用断开不会发送 System_OFF。原厂界面可能停止共享采样，此时显示的值会变旧；用户点击刷新可再次请求采样，不自动争抢控制权。

能力与 Fan/Status 每 15 秒刷新，保活每 10 秒发送。传感器依厂商服务节奏推送；GPU、电池等主题并不保证每轮都有消息。超过 15 秒未收到该主题时保守标记为旧数据，不以 socket 保活或其他主题更新延长其新鲜度；这也不等于硬件故障。

retained 数据始终标记缓存；实时消息标记接收时间；断开后所有已收到的值标记历史值并变淡。缺失、无法解析及非有限数值显示未知，不用 0 或旧轮次数据补齐。

- WinUI 3 Release 构建：零警告、零错误，使用 Windows App SDK 1.8，x64、自包含、asInvoker、PerMonitorV2。
